# Persistent task routing

Version 0.6.9 carries a task journey across observed menus, modals, SPA states, document loads and linked popup tabs. The original goal, destination value, routing preference, verified progress and recalculation count live in the extension session. Only user interactions with observable outcomes advance progress. Opening a language menu does not complete “Change language to Spanish.” A selected preference or an observed Spanish document does. Account-language goals require setting evidence rather than merely a Spanish document.

The destination parser recognizes generic change/set/switch/choose/select requests with a purpose and a value. Other requests retain the grounded semantic/model intent pipeline. Language names use browser `Intl.DisplayNames` locale data; destination links expose authored `hreflang`. Native selects expose bounded sanitized option labels, enabled flags and selection states, never option values. There are no Wikipedia product selectors, article URLs or per-site task scripts.

Login and account creation now carry a workflow objective, even without a destination value. Generic wording normalization matches login/log in/sign in and create account/register/sign up while preserving qualifiers. Declared links and menus are entry points; submitting credentials or creating an account stays a review boundary. Form-local labels, submission labels and authored autocomplete/input-type hints identify authentication forms. A page heading alone cannot label unrelated appearance or search forms. Safe fields progress by observed focus, without reading their values; focus never establishes authentication success. Existing stored plain auth journeys upgrade on restoration.

Chrome webNavigation metadata connects a clicked authentication link to a browser-confirmed server redirect. Only an active auth task, a matched starting URL hash, the pinned tab or linked popup, a link transition and a recent server-redirect event qualify. The resulting host and full-destination hash replace the expected endpoint in session memory. Raw redirect queries are never saved. Redirects do not grant DOM access or prove login/account creation. Continue task here still requires that specific host grant and checks the final URL. Unrelated, typed, client-script and ordinary preference redirects remain unaccepted.

Unresolved and awaiting-choice plans show an unavailable estimate, rather than a zero-click/zero-second promise. Their reason is visible beside the active journey. Authentication routes remain learning routes at submission review because successful authentication is not established.

The optional on-device model receives the original destination and the last eight verified interactions with every follow-up observation. Requests occur as the task moves to another state. Fresh session clones keep untrusted pages and prior model guesses from acquiring authority while structured task state carries context. Responses remain constrained to current ordinary control IDs. Revisions, documents and journey IDs reject late responses. Existing accepted intent survives an invalid follow-up. Models cannot assert completion, execute clicks or cross action boundaries.

The graph stores observed UI-state transitions, including distinct menu states sharing a URL. Dijkstra computes the lowest-cost known path within a twelve-transition planning horizon. “Fewest clicks” assigns one unit per observed control interaction; “Fastest known route” uses observed mean guidance-to-result durations, conservative default costs and a penalty for old or singly observed transitions. A slower direct preference can lose to a faster observed detour. This optimizes the observed graph and cannot establish a global optimum over unseen screens. Focus, section arrival and native option selection count as interaction steps, so click estimates are approximate. Host-permission prompts can add interactions outside the website route estimate.

Estimates show a range, interaction count and estimated/observed/mixed basis. Unknown screens are provisional and may add steps. Previously observed upcoming controls are distinguished from predicted destinations. Predictions never supply executable IDs for future pages or become verification evidence. Generic intermediate routing uses declared ownership, control purpose and previously verified openers. Uncertain or opaque effects remain unresolved. User-entered fields are never filled by Navigator.

IndexedDB database version 2 preserves the sites store and adds a tasks store. Saved tasks contain sanitized goals and destination values, route preferences, planned label/signature summaries, estimates and bounded verified journeys. They contain no ephemeral control/document IDs, raw queries, input values or selectors. Draft plans are saved immediately; a draft does not replace a previously completed route. Saved routes can be forgotten individually and are recalculated with current controls when reused. Website changes invalidate signatures and stale first edges; historical future steps are rechecked on arrival. Restored completed preferences are revalidated after reload.

Knowledge remains limited to 50 sites, 100 latest pages, 120 state snapshots (8,000 state controls), 30 templates, 5,000 latest-page controls and 400 transitions per site. Task routes are capped at 100 globally, with 30 retained verified steps and up to 24 planned/predicted labels per route. Knowledge expires after 90 days when accessed. Forget website removes its routes and routes that traversed it; Clear removes both stores. Individually forgotten routes remain suppressed for the active session, including worker restarts, until a new task is requested.

The task stays pinned to its current tab/origin. Expected cross-origin destinations and `_blank` links offer **Continue task here**. Chrome can withhold the new tab's URL until host access is granted. In that case, Navigator retains the expected origin from the actual clicked link and offers permission without claiming arrival. Continuation checks the actual URL fingerprint, target origin and originating tab relationship after host access is granted, before observation or progress. The button requests only that site's access under a user gesture. Known unrelated destinations stop; opaque destinations remain unverified and a mismatching URL is rejected after the grant. Closing/removing a clicked picker link preserves the pending destination until arrival or the existing deadline. The live Spanish Wikipedia regression independently reaches the Spanish document but cannot claim Navigator completion before the native permission grant; permitted local-origin fixtures verify continuation, completion and redirect rejection. Permission prompts remain native handoff checks.

Tests cover Spanish intent, live `hreflang` choices, actual selected options and wrong values, ambiguous destinations, account-language scope, weighted alternatives, cycles/stale/inferred edges, timing samples, state retention, bounded model context, secret exclusion, changed-site saved-route reuse, full-document intermediate screens, popup tabs and cross-origin continuation. Deterministic model tests check the adapter contract, not Gemini Nano language quality. The 116-case accuracy matrix keeps its declared scope; additional journey regressions are reported separately.

This is a stateful navigation and route-learning algorithm with an optional existing local language model. It introduces no custom trained model, OCR, cloud provider or background site spider. Inaccessible frames/closed roots/canvas, poorly labeled controls, ambiguous effects and unknown future screens remain limitations. Complex arbitrary workflows depend on available live semantics, observed history and model quality and are not guaranteed by this implementation.
