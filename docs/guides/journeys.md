# Continuous journeys and return routing

The original objective, requested values, exclusions and completion criteria are independent of the current control, document and predicted route. Opening a language picker or deployment entry point does not complete the user's destination. Each new screen requires fresh binding and task-specific evidence.

The shared interpreter parses full English requests into up to three ordered tasks. Internal workflow milestones do not consume queue slots. Corrections update compatible entities/objectives and invalidate dependent steps. Ambiguous references require grounded clarification rather than inherited guesses. Pause retains the queue; Stop cancels it. Skip records skipped, not success.

## Context and continuity

Journeys survive menus, dialogs, SPA states, documents and recognized authorization/tab handoffs. Credentials and 2FA have no task-expiry deadline. Ordinary waiting becomes recoverable after two minutes; meaningful new evidence resumes planning. Recovery refreshes priority surfaces, widens retrieval, reconciles structure and uses OCR only when eligible, once per relevant revision.

Bounded graph search replaces the old twelve-transition cutoff. Exhausting a search budget preserves the objective and reports that the next step is still being found. Every 25 verified interactions, a checkpoint retains recent detailed events, compact milestone summaries and breadcrumbs. Checkpointing never completes or cancels a task.

New destinations can pause unfinished journeys. Up to five are retained in trusted browser-session storage; when full, the user chooses which to replace. Resume always obtains a fresh observation. Unrelated navigation pauses context rather than silently adopting an unrelated screen.

## Routing and return actions

Observed screens, controls and verified transitions form a bounded graph. Fastest routing uses observed durations plus conservative costs; fewest-clicks minimizes known interaction cost. Estimates cover observed/predicted steps and cannot establish the shortest path across unseen pages.

Routes can guide a live control, observed dismissal, one relevant browser Back step, an associated tab switch or an unverified visual suggestion. A forward edge is never presumed reversible. Fresh global navigation is preferred when it avoids a detour. History/tab actions require a relevant ledger relationship and verification afterward. Stale history, closed tabs, account changes and unsaved-change warnings pause the route.

Documented workflow milestones and observed edges remain distinct. Missing controls can lead to grounded exploration of a live menu/search surface; predictions never invent URLs, selectors or executable future IDs. Every actionable target must be rebound against its current interface.

## Verification and saved routes

Focus, expansion and section arrival establish only their specific requested outcomes. A search term survives manual entry/results until the requested destination is verified. Review clicks and visual changes start checks; they never independently prove successful creation, deployment or cancellation. Wrong-subject statuses and unrelated toasts cannot complete the request.

IndexedDB v5 preserves original knowledge and parameterized reusable routes. Private entity names and supplied values remain in session context; saved routes ask for parameters again. Stored routes omit ephemeral bindings, selectors and coordinates. Reuse revalidates current controls and affected transitions. Derived indexes can rebuild without deleting original knowledge.

Saved routes can be forgotten individually. Forget website removes routes traversing that website; Clear removes all persistent knowledge. A draft/learning route does not certify a completed task.
