# Page context and grounded intent

The collector now attaches a structural context to each actual control: ordered heading ancestry and named regions such as navigation, main, toolbar, form and dialog. It builds heading outlines within structural boundaries, then adds enclosing section headings and page headings. A footer does not inherit an unrelated article heading. References use the owning document or open shadow root. Structure uses generic HTML/ARIA; no website selector, URL route or article name enters this code.

Semantic matching uses the full heading/region context alongside control labels and descriptions, so repeated Edit controls can be distinguished by nested section qualifiers. Extra qualifiers in the nearest section reduce its rank: Edit Plot prefers the Plot section over Plot inspirations. This is a generic specificity rule. Unknown scope remains unknown. Structure changes alter signatures and revision numbers, invalidate pending guidance and update bounded browser-local memory. Sanitized structural metadata is retained with the control. Viewport placement is a transient categorical hint, omitted from persistent site knowledge; raw geometry, editable contents and field values are never model input.

The optional model receives a retrieved view of the current observation, rather than the first 180 controls in DOM order. Retrieval ranks generic purpose evidence, requested terms and interface controls, includes each selected target's discovered opener, and bounds input to 96 controls and approximately 24,000 characters of control metadata. Page language, layout, scan completeness, omitted counts, states, scope, popup type, reveal relationships and sanitized destination paths accompany that view. A control omitted by the collector's 600-control cap remains unavailable; retrieval cannot discover unloaded pages or inaccessible frames. A large model prompt can still exceed a browser model's token window and fall back.

Each request clones a pristine Chrome Prompt API session, uses cancellation and a 30-second timeout, and destroys its clone. Version 0.6.8 supplies the original destination, routing preference and up to eight verified interactions as structured task context on each current-page follow-up. Old raw pages and model responses do not acquire authority through accumulated chat history. The task carries context while current IDs and effects are revalidated. Enabling the base model retains the user-activated download flow; everything runs locally. See [task routing](task-routing.md).

Structured model output contains current control IDs, confidence and an intent: target purpose, requested context, page/section/any scope, and focus/reveal/choose/navigate/locate operation. The model may translate a paraphrase into the page's vocabulary. The planner independently finds an unambiguous eligible live route for that intent, requires the selected IDs to match that route, checks declared control kind against the proposed operation, and requires section/context qualifiers to come from the user's request. Scope constrains target eligibility while all discovered opening relationships remain available. Clear original semantic matches take precedence over conflicting proposals. Consequential and unknown-effect boundaries survive reinterpretation. Confidence is a heuristic, not a calibrated probability.

Accepted intent stays in the active goal plan. After a menu replaces its children or another target changes, replanning uses the same interpreted purpose against fresh observations and IDs; it does not reuse the model's old IDs. A new user goal cannot inherit a previous goal's interpretation. Observed results, not model text, determine verification. Opening a menu asks for a choice, focusing a search field does not establish a completed search, and navigation verifies the actual destination. Site memory still learns only visited structure and observed interactions, not model weights or imagined website routes.

Coverage includes nested heading qualifiers, changed structure and memory versions, late-control retrieval with opener retention, invalid/empty model fallback, invented IDs/context, dropped user qualifiers, tied controls and committing boundaries. Browser adapter tests use a deterministic model fake and replace a hidden menu child before proceeding to an independently checked destination. Live Wikipedia checks cover both unqualified article Edit and explicit Plot section Edit with actual halo geometry; they do not publish an edit. Existing live accuracy gates run with AI off. Real Gemini Nano paraphrase quality and native Chrome/model availability remain separate acceptance work. OCR, image inference, cross-origin frames and closed roots are deferred.

API reference: [Chrome Prompt API structured output and session management](https://developer.chrome.com/docs/ai/prompt-api).
