# v0.9.0 implementation and validation

Continuous journeys retain objective, requested values, exclusions and outcome predicates independently of the current document or control. Every 25 verified interactions creates a compact checkpoint; the detailed history remains bounded to 30 events. Heap-based graph search has no twelve-step cutoff, preserves its frontier between bounded planning slices, and revalidates the first live edge. Budget exhaustion does not complete a task.

Five unfinished journeys can be retained in trusted browser-session storage. Resuming requires a fresh observation. The session ledger records only Navigator-observed documents, SPA states and surfaces. Browser Back recommendations name one observed predecessor at a time; forward interactions are never assumed reversible. Site controls and observed dismissal mechanisms remain user-performed. New GitHub repository guidance describes creation-menu, form-entry, input, review and requested-item verification milestones using official documentation, without destination URLs or selectors.

`packages/vision` supplies pinned CPU Tesseract recognition, bounded contracts, a replaceable queue and grounded fusion. Packaged scalar/SIMD LSTM engines and English data work offline. A separate worker runs only when refreshed discovery has insufficient evidence. MiniLM also interprets recognized labels using session-only embeddings; image confidence cannot establish known effects or task completion. Visual suggestions use dashed highlights and retain unknown effects. The current-page check reruns observation and planning rather than asserting success.

Capture covers the active authorized HTTP/HTTPS viewport. Editable fields and frames without verified access are masked; overlays are hidden during capture. Unknown/redirected frame mappings remain masked. Navigation, viewport changes and interactions cancel stale recognition. Images and recognized private text are temporary. Browser processing is the default; the explicit backend OCR setting permits temporary image transmission to the configured service. The authenticated `/v2/ocr` API validates PNG dimensions, four MB/four megapixel limits and returns stamped regions; its worker has no SQLite access. Existing API protocols remain available. IndexedDB v5 and SQLite migrations preserve original knowledge and require fresh control binding.

The frozen 64-case corpus covers 40 supported Cloudflare/GitHub requests, 12 ambiguous and 12 unsupported requests. Deployment-method questions receive an explicit fixture answer before route coverage is assessed. This tests grounded next targets, not signed-in full-site execution. The original 200-case NLP corpus, 360-case corpus and Wikipedia matrix remain frozen.

Release packaging requires passing reports for the matching extension/API bytes, including new OCR, held-out routing, performance and production-browser checks. Detailed results are generated under `output/vision`, `output/nlp`, `output/multi-app` and `output/acceptance`. Performance uses a 1920 × 1080 synthetic viewport and ten warm OCR samples on documented CPU hardware.

Pending user-assisted checks: native Chrome toolbar activation/capture permission recovery; signed-in Cloudflare Pages Git integration and Direct Upload; actual GitHub repository creation and account variants. These checks must not be counted as automated passes. OCR reads visible text; icon-only controls, native dialogs and unseen screens still require other evidence.

Creation verification requires a fresh, named creation receipt or created-item signal. A matching repository heading alone is insufficient. If a signed-in interface supplies no such evidence, the task remains unverified.
