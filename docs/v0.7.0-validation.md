# v0.7.0 validation and installation

The default navigation path now uses Compromise, lexical BM25 and a bundled,
CPU-only MiniLM model through the shared navigation core. The extension owns
live discovery, fresh binding and outcome verification. The optional
Fastify/SQLite backend uses the same core in a worker thread; browser knowledge
remains authoritative and backend failure falls back to local processing.

Requests retain their original English sentence, requested values, qualifiers
and exclusions. Grounded clarification does not require retyping. Up to three
explicit tasks run in order; each outcome must be verified before the next task
starts. Pause retains the queue, Stop cancels it, and Skip records a skipped
task. Search-field focus is intermediate progress for an article search.

## Install and native verification

Reload `dist/extension` at `chrome://extensions`, confirm **0.7.0**, then refresh
the website tab. To use the offline ZIP, extract it and Load unpacked its
folder. Try **Could you help me change language to Spanish?**, or **Please
search for Saturn**. The user performs every click and input.

The optional backend package includes the model and compiled server. Extract
it, change into its `package` directory, run `npm ci --omit=dev`, then `npm start`.
Follow [backend setup](api-setup.md) to configure the generated bearer token
and exact extension-origin allowlist. The packaged CLI startup smoke test
verified authenticated health, a generated token and an empty default origin
allowlist.

Native Chrome toolbar activation, permission grant/denial/retry, keyboard
interaction and actual screen-reader announcements remain pending in the
[native handoff checklist](chrome-handoff.md). Native computer APIs were
disabled during this implementation. Automated Chromium extension tests do
not establish those native checks. OCR, custom training, multilingual requests,
multi-user accounts and cross-device synchronization remain future work.

Source baseline: `a275b0e`. Changes remain local, uncommitted and unpublished.
Earlier versioned archives and reports are preserved. Development failure
reports include the pre-context correction, startup retry, menu-handoff gap,
stale-plan state and diagnostics-download timeout, and an isolated long-stall
live timeout; they are retained separately from final passing
evidence. The timeout's precise cause is unestablished, and no acceptance
threshold or live assertion was weakened.

Simultaneous live and accuracy runs also encountered stalled Chrome messaging
during startup or goal submission. Their reports and traces are retained as
`v0.7.0-concurrent-live-message-timeouts` and
`v0.7.0-concurrent-accuracy-timeout`. The final full regression and live gates
were rerun individually; the final accuracy run followed the live gate on the
same unchanged build. The precise cause of those messaging stalls remains
unestablished.
