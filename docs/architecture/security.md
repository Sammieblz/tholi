# Trust and lifecycle boundaries

Page text, observations, stored knowledge, documented predictions and model output are untrusted evidence. Every highlighted control requires a fresh document/element binding, eligible visibility, enabled state and matching signature. Model output cannot provide selectors, JavaScript, clicks or authoritative outcome claims. Exclusions and scope survive reinterpretation.

Both targets use `activeTab`, `tabs`, `scripting`, `storage` and `webNavigation`. Chromium additionally uses `sidePanel` and `offscreen`; Firefox uses `sidebar_action` and its MV3 event page. Private settings use protected Chromium storage or Firefox extension-origin IndexedDB. Default host grants cover English Wikipedia and local development. Other ordinary HTTP/HTTPS origins require specific site access. Installation does not grant every site. DOM permissions and viewport-capture permissions are tracked separately; Chrome may require renewed toolbar activation for capture.

Live sessions pin origin, tab, session and document identity. Expected document/authentication/popup handoffs retain the objective but require the actual permitted destination before repinning. Unrelated navigation pauses the retained task. Navigation metadata is scoped to active journeys, not general browsing history. Association with a redirect does not prove that login succeeded or that a destination is trustworthy.

Commands require the extension identity and appropriate extension-owned sender. Content updates require assigned tab/frame/document identity and validated contracts. Loading invalidates visible bindings; stale asynchronous results cannot restore an older document or complete a newer task. Pause remains paused through loads; Stop prevents reattachment. Resume requires fresh observation.

Users perform website clicks, field input, credential entry and submissions. Tholi may scroll a freshly bound target and display guidance. Automatic scrolling is canceled when the user intervenes. Review targets explain the consequential or unknown effect; a click only starts verification. Risk classification is heuristic and cannot establish arbitrary JavaScript/server behavior.

Completion requires fresh task-specific state: the requested selected preference, destination, item or status. Finding an entry point, opening a menu, OCR text, a changed image, unrelated success toast or user confirmation cannot independently prove completion. Skip is recorded as skipped. Predictions and saved routes never authorize stale controls.

The background vision service owns capture authorization and cancellation. It binds a capture lease to the actual pinned tab, focused window, native document, zoom, request, journey and observed page. Content supplies only DOM viewport geometry and a complete mask proof. Checks span native capture, processing and final use; an asynchronous backend send guard runs after health, permission and protected-setting waits. Scope changes cancel queued or active work. Restoration of hidden overlays does not refresh or replace the retained proof.

The shared OCR worker paints opaque privacy masks at native resolution before any resize, crop, grayscale conversion or inversion. The same stage handles both images in region comparison. Source PNG admission precedes bitmap allocation; output contracts and measured source-plane geometry are validated independently. One active job and one replaceable pending job prevent an image backlog. Backend fallback reuses prepared masked input, and raw captures are not transmitted, persisted or logged. Resource cleanup closes bitmaps and releases canvases on success, failure and cancellation.

Native closed-shadow access is restricted to the privacy traversal; it does not reveal closed controls to discovery or authorize interaction. Budget exhaustion, unavailable native shadow access, unsupported private paint, pinch/pan geometry and unverified Firefox gutter geometry refuse capture while structured guidance remains available. Pre/post checks cannot make DOM inspection and the browser screenshot atomic, or identify arbitrary private pixels painted by a page. See [privacy](privacy.md) and the [masked-capture validation record](../development/testing/masked-capture-validation.md) for exact bounds and evidence. Visual-only targets still retain unknown effects and manual review; OCR text or matching pixels never establish arrival.

The optional API binds loopback by default, requires a bearer token and explicit extension-origin CORS, and executes inference outside the API event loop. Self-hosted remote connections require HTTPS. Credentials stay in trusted extension contexts; private entities, input values and OCR payloads are not persisted or included in payload logs. See [privacy](privacy.md) and [API setup](../guides/backend.md).

Synthetic tests and Wikipedia checks do not constitute a security audit of arbitrary websites. Native browser access recovery and signed-in workflow verification remain separate pending checks.
