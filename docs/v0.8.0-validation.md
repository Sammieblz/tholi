# v0.8.0 validation and installation

This candidate adds incremental discovery and contextual workflow guidance to
the offline Compromise/BM25/MiniLM engine. General HTTP/HTTPS discovery is
independent of the six documented platform guides. Every interaction remains
user performed and every highlight requires fresh live control evidence.

## Activation failure and fix

The GitHub screenshot was reproduced with an ungranted GitHub tab using the
production extension. Chrome omitted its URL, so the extension offered no task
before it could request website access. The `tabs` permission now supplies the
active-tab URL; scanning still requires the selected site's explicit host grant.
Start requests the fresh active origin, and the worker rejects a tab/origin change
during permission approval. Permission denial starts neither a session nor an
overlay. No browsing-history collection or automatic scanning of all tabs was
added.

A production Chromium test checks activation on ungranted Cloudflare, GitHub,
Jira tenant, YouTube, Netflix, Amazon and an unrelated website. It checks the
enabled **Allow website access and start** action before scanning and a scoped
permission-denial path. This does not replace the pending native Chrome check.

Tests cover complete simulated journeys, wrong outcomes, review boundaries,

Browser fixtures cover nested/portalled menus, recycled controls, open shadow

deletion barriers and preservation of previously committed knowledge on timeout.

Final live runs initially recorded compact-layout polling timeouts before a
section-edit request and after opening a language picker. Isolated unchanged-build
checks passed, but the full rerun reproduced the language failures. Traces showed
sidebar reads waiting behind the same command queue that awaited memory work.
Storage was moved to the separate queue described above; the deliberately blocked
writer test and both compact-layout language checks pass on the rebuilt extension.
The first failure report is retained at
`output/qa/v0.8.0-final-live-first-run.json`, with second-run language traces in
`output/qa/v0.8.0-final-live-{spanish,picker}-second-run.zip`. The underlying reason
for the storage stall is unestablished; no assertions, corpus expectations or
deadlines were relaxed.

A subsequent full browser run stalled on semantic retrieval after removing the
References heading, then on another live NLP request. That trace is retained at
`output/qa/v0.8.0-dreamworks-message-stall.zip`. Derived-cache reads/writes were
also synchronous inference dependencies. They now use bounded cache reads with
CPU fallback and background writes; worker failures/deadlines return errors
instead of leaving requests pending. The blocked-store regression covers both
knowledge and embedding/index stores, and verifies that a nonexistent control
remains unresolved. Both previously stalled live checks pass on the rebuilt
extension. The NLP browser reporter now requires 12 cases, including this added
regression; the previous 11 cases and their assertions remain present.

The full extension run then passed 84 cases but exposed missing cold memory
hydration after browser restart in both layouts. The first explicit memory read
now loads existing IndexedDB knowledge outside the guidance queue; a deletion
epoch prevents late hydration from restoring cleared cached data. Both unchanged
restart/Clear assertions pass on the rebuilt extension. The earlier report is
retained at `output/qa/v0.8.0-cold-cache-before-hydration.json`.

The final live suite also exposed a different picker race: “Change language”
was interpreted as `choose`, while the handoff guard covered only `reveal`.
After a verified opening, replanning selected the popup search field. The guard
now covers both intents using the same fresh expanded-control evidence; an
unspecified preference remains incomplete and cannot advance a following task.
The regression covers that distinction without changing the frozen corpora.
The trace is retained at `output/qa/v0.8.0-final-picker-verification.zip`.

## Installation and remaining verification

Reload Navigator in `chrome://extensions`, confirm **0.8.0**, refresh GitHub,
then click its toolbar icon. Choose **Navigate this website** and
**Allow website access and start**. Granted sites show **Start navigation**.
Describe the task and follow the highlight yourself. The current unpacked folder
is `dist/extension`; a packaged ZIP can be extracted and loaded unpacked.

Native Chrome reload, permission grant/retry and actual screen-reader checks
remain pending. The native computer-use bridge was unavailable in this session.
Automated extension tests establish browser API/fixture behavior, not that the
user's existing Chrome instance has reloaded the build.

Public discovery checks and signed-in workflows are reported separately in the
[capability matrix](v0.8.0-capabilities.md). Account variants, actual deployment,
creation, plan change and cancellation require user-assisted checks. A click or
**Check result** only starts verification and cannot establish success.
Closed shadow roots, canvas-only controls, native file pickers and inaccessible
frames remain limits. General website access does not guarantee completion of
every task. OCR, vision and required LLMs remain deferred.

The optional backend uses the same core and is documented in
[backend setup](api-setup.md). Changes and artifacts remain local; earlier
versioned releases are preserved.
