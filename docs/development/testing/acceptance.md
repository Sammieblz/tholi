# Declared Wikipedia acceptance benchmark

The matrix is declared in `tests/browser/acceptance/matrix.json` before evaluation: five structurally different articles, six control-goal families and two viewport sizes, for sixty supported attempts. Goal contracts specify the observable result. Showing languages means opening the picker and awaiting a choice; showing search means focusing the field, not submitting a search. Explicit language choice/destination arrival is additional boundary coverage in #18. Test URLs and ground-truth selectors are test data only and do not enter product code.

Ground truth comes from independent browser assertions: actual input selection, active field, References geometry and the site's actual language picker. Expected target roles/names are declared by the fixture harness rather than copied from the planner. A refusal or timeout remains a failed supported attempt in the denominator. A test cannot improve the result by silently skipping an article or control. Infrastructure failures and missing sample attachments also fail the gate. Synthetic ambiguous, missing, stale, destructive and unrelated-effect cases are reported separately from live Wikipedia results.

Target precision is correct emitted highlights divided by all emitted highlights. State/outcome verification precision is correct verification claims divided by all verification claims. Supported completion is attempts whose declared observable result is reached and correctly reported divided by all declared supported attempts. Report refusals, stops, model calls and counts alongside those ratios. Zero-denominator metrics fail rather than becoming 100%. The gates are >=98% target precision, >=95% verification precision and >=90% supported completion, with zero false success, Navigator automation or known sentinel leakage in the tested cases. These measurements are sample results, not a claim of universal website accuracy.

Each attempt records its case ID, environment, target decisions, verified-result decisions and completion/failure. Reports include matrix hash, extension/protocol version and source revision/working-tree state. Optional AI is disabled. Retained failures identify their case rather than leaking actual browsing data.

Browser assertions retain their declared bounded test windows. The production coach now uses state-aware waiting: ordinary waits become recoverable after two minutes and authentication has no task-expiry deadline. Earlier eight-second runtime behavior and v0.6.4 delayed-picker failures are historical evidence. The frozen matrix and denominators remain unchanged. Known failed cases block packaging even when aggregate ratios exceed the numeric gates.

Full browser-regression reporters record collected case IDs, status, suite owners, validation tier/run and exact build hashes. Hardcoded suite totals no longer authorize packaging. All required owner files must run and every collected case must pass exactly once. Filtered/focused and PR runs cannot certify a release, even when their selected cases pass. Full certification also requires the same coordinated run, exact extension/API/website bytes, pinned assets and the complete acceptance scenario IDs. See [testing and CI](README.md).

The live geometry oracle uses actual target bounds after scrolling. A tall live fundraising banner can place the article below the viewport when returning to document top; that state requires the appropriate direction cue, rather than an on-screen halo. Both modes are asserted independently. The failed pre-correction report remains in `edit-banner-live-regressions.json`; final full-suite results are in `live-regressions.json`. See `edit-iteration-notes.json` for retained failures and corrections.

The 13 authored static golden states remain declared in the unchanged matrix but execute once in `tests/unit/navigation/core.test.ts`, preserving exact state/status/target expectations. They no longer run the same engine-only assertions under two browser viewport names. The browser matrix retains all 60 live and 30 generic scenario IDs, thresholds and independent outcome oracles. Full certification requires both the unit evidence and browser acceptance reports. Historical 116-case reports include the former 26 authored browser executions and describe their dated builds only.
