# Trust and lifecycle boundaries

Page observations and persisted site memory are untrusted evidence. Models return a bounded list of discovered control IDs; they cannot supply selectors, JavaScript, clicks or outcome declarations. Every chosen control is rebound to the current DOM and checked for visibility, enabled state, signature and document freshness. Hidden model steps must follow a discovered reveal relationship. Invented IDs, tied semantic goals, unsafe controls and stale revisions are rejected.

The extension uses activeTab, scripting, sidePanel and storage. Existing host grants cover local development hosts and English Wikipedia. Optional host patterns allow user-granted access to a specific website at Start or task continuation; installation does not grant every website. Live sessions pin an exact origin, tab, session UUID and document ID. An expected composite-task destination may retain context at a cross-origin/popup boundary. Chrome may withhold the destination URL before host access, so the panel can offer access to the clicked link's expected origin without asserting arrival. Continue requires a matching actual URL fingerprint, origin and originating tab relationship after existing/user-granted host access, before repinning or observing. Known unrelated cross-origin navigation stops; opaque destinations cannot advance progress and mismatches are rejected after permission. Authored demo boundaries remain unchanged.

Commands require the extension ID and extension-owned side-panel sender URL. Content updates require the assigned tab, matching session/document, allowed sender origin and validated schemas. Loading clears the visible controls and rejects stale document observations. A delayed click-intent publication may be retained during loading without restoring the old document's running state. Destination verification happens before constructing the replacement coach, so counters and completed goals cannot be overwritten by an older coach. Pause persists across loads; Stop prevents reattachment.

Verification checks actual focus, checked/expanded state, selected index (without reading values), related control/state changes, section viewport arrival or the expected loaded URL. Clicks alone are not success. Unknown action-button effects remain unverified unless a structural effect is observed. Risk-word/form-method classification stops before detected consequential actions; it is a heuristic, not an exhaustive semantic or security guarantee. No code path clicks, fills, submits or scrolls the website.

Task completion uses the retained objective's actual state. A wrong native selection or merely opening a menu cannot complete a requested value. Predictions and saved routes never grant authority to stale control IDs. Model follow-ups also require the same journey ID, document and revision. Saved route goals and plan metadata remain browser-local and can be deleted; diagnostic exports omit them.

The scanner handles rendered semantic controls and open shadow roots, caps observations, and reports partial scans. Cross-origin frames, closed roots and canvas-only interfaces are outside this adapter. Synthetic security/privacy tests and live Wikipedia checks do not constitute an audit of arbitrary websites or model prompt-injection robustness.
