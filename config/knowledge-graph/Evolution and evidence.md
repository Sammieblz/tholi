# Evolution and evidence

Tholi grew from a controlled navigation demonstration into generic live discovery, retained journeys, offline language interpretation, contextual platform guides and masked OCR assistance. The continuing invariant is that a click, focus, menu reveal, review action or animation cannot by itself establish the requested outcome. Historical passing reports describe their declared cases and evaluated bytes. They do not certify today's checkout or authorize packaging, deployment or publication.

This note covers all 17 release Markdown documents outside `docs/releases/v0.10.1/`. The companion [[history.json]] preserves version-scoped concepts, exact source lines, explicit citations and separately marked inferences. Current source paths in its `evidence_files` are navigation aids for the code graph; they do not assert that present source equals a historical archive.

## 11 October: declared evidence, effects and generic discovery

The [v0.6.5 record](../../docs/releases/v0.6.5/build-evidence.md) establishes the early measured acceptance boundary: five structurally different Wikipedia articles, six goal families and two layouts gave **60 supported live attempts**. With 26 generic and 26 authored cases, the matrix contained **112 attached cases**. The historical run measured 71 correct live targets, 71 correct verification claims and 60 supported outcomes. Its zero measured false success, automated website actions, synthetic sentinel leakage and model calls were claims about those declared cases, with optional AI disabled. A language picker meant waiting for choice; search-field focus meant focus. Authored fixture state conformance was distinct from live goal completion. Reports bound the ten evaluated extension files and the ZIP readback to matching bytes. Native keyboard, screen-reader, permission, reload and destination-origin handoff work remained open.

The [v0.6.6 Edit correction](../../docs/releases/v0.6.6/build-evidence.md) addressed a classifier that rejected ordinary Edit navigation and inherited committing words from unrelated surrounding context or form URLs. The generic owner learned to distinguish entry navigation, popup reveal, field focus, form submission and committing operations. Implicit submit, external form association, method/action override and GET operation cases gained coverage. Opaque Edit retained an unknown-effect boundary; publishing remained a review boundary. Page and section context disambiguated Edit scope and affected fresh fingerprints. No Wikipedia-specific product selector or URL route was introduced.

This revision added generic negative cases for opaque Edit and implicit POST, changing the matrix from **112 to 116 cases**: 60 live, 30 generic and 26 authored. The six live goal families stayed unchanged. Separate live Edit checks verified the toolbar target and actual highlight geometry; they never published an edit or established a complete editing workflow. Final historical checks were 83 units, 60 extension browser regressions, 10 live regressions and 14 benchmark tests. Retained failures documented scope, export timing and fundraising-banner geometry corrections without changing case denominators.

The [v0.6.7 record](../../docs/releases/v0.6.7/build-evidence.md) marks a consequential ownership change. The prior Wikipedia-specific coach, route packs, sample allowlist, URL policy, `scope`/`continueOnNavigation` schema fields, inspection helpers and superseded tests were removed. The authored route engine survived for the controlled demo. Live navigation instead used generic control discovery, context, matching, fresh binding and verification. This split remains important when reading [[Architecture]]: a demonstration route is not authority over a live extension session.

Controls acquired heading ancestry, named regions and transient viewport placement. Nested context resolved the reported Edit Plot versus Plot inspirations ambiguity. Structural changes invalidated signatures/revisions; transient placement did not become durable semantics. Optional on-device model retrieval used bounded, goal-ranked controls with opener ownership, states, scope and omission counts. Each request cloned a pristine session, timed out after 30 seconds and destroyed the clone. Structured proposals still needed an unambiguous live route and compatible scope/effect. These deterministic browser contracts **did not measure actual Gemini Nano quality**. The semantic acceptance matrix ran with AI off.

The actual French-language navigation test stopped at the ungranted destination origin without claiming completion. Top-document and open-shadow-root semantics were supported then; inaccessible frames and canvas-only controls were outside that historical adapter. Later coverage must not be projected backward. The 94-unit, 64-extension and 10-live results remained scoped historical evidence. The unchanged 116-case matrix had 72 live interactions on this run rather than 71 because a revealed-control path differed; the number of cases did not change.

## 11 October: persistent destinations and guarded authentication handoffs

[v0.6.8](../../docs/releases/v0.6.8/build-evidence.md) retained the original destination and verified progress through menus, modals, intermediate documents and linked popup tabs. Browser-owned IndexedDB stored reusable tasks; resumed routes rebound current controls after changes or browser restart. Weighted observed routing compared fastest/fewest-interaction paths through the bounded known graph. Predicted upcoming steps and unknown screens remained provisional. The panel allowed one outstanding poll and ignored replies after teardown; redundant full-memory transfer was removed.

Spanish navigation exposed Chrome's withheld URL for an ungranted origin. The clicked link's expected origin supported the access request, after which the extension checked the actual URL and originating tab before observing or advancing. The live test established the retained task at that boundary. Permitted local fixtures established completed continuation; **the actual native host grant was still pending**. Historical checks were 105 units, 78 extension and 12 live regressions with the same 116-case, AI-off matrix. Some zoom/message stalls had no established precise cause even though final full suites passed unchanged assertions and timeouts.

[v0.6.9](../../docs/releases/v0.6.9/build-evidence.md) expanded retained intent to login and account creation without requiring a destination value. Entry links and menus stayed distinct from credential submission. Form-local metadata identified safe focus without borrowing an unrelated heading; focus never proved authentication success. The new `webNavigation` permission associated a recently selected authentication link with a browser-confirmed server redirect in the pinned tab or linked popup. Stored redirect evidence was origins and URL hashes, never raw query strings. Typed, unrelated and client-script navigation could not supply that evidence. The destination still needed its own host grant and exact final-URL validation.

Four real-page regressions followed entry links and inspected real authentication forms. Their test-only username collector was **not evidence that the extension observed the new host after a native grant**. No credentials were submitted or accounts created. The record reports 117 units, 86 extension and 16 live regressions; an initial 15/16 live run and earlier long timeout were retained. The later unchanged full pass did not establish the transient failure's precise cause.

## 12 October onward: real local NLP and structural arrival

[v0.7.0](../../docs/releases/v0.7.0/validation.md) made **Compromise interpretation + lexical BM25 + bundled CPU-only MiniLM** the default through the shared navigation core. The optional Fastify/SQLite backend ran the same core in a worker. Browser knowledge stayed authoritative and failure fell back to local processing. This actual CPU embedding inference is different from the earlier deterministic optional-model contract and from an LLM call.

Requests retained their original English sentence, requested values, qualifiers and exclusions. Grounded clarification avoided retyping. Up to three explicit tasks ran in order, each requiring a verified outcome before the next. Pause retained the queue, Stop canceled it and Skip recorded a skip. Search focus remained intermediate progress.

The frozen 200-case NLP corpus had 120 calibration and 80 held-out cases, including 48 supported held-out positives. Historical results were:

| Pipeline | Accepted-target precision | Supported coverage |
| --- | --- | --- |
| Existing matching | 40/40 | 40/48 |
| Raw embeddings without abstention | 55/80 | 48/48 |
| Hybrid interpretation, retrieval and eligibility | 62/62 | 48/48 |

Similarity therefore supplied retrieval evidence rather than completion authority. The historical corpus recorded 92 embedded texts, 8,043 cache hits and zero LLM calls. The record reports 121 units, 10 real-model/API/migration tests, eight offline NLP browser tests, 86 extension regressions, 16 live regressions and the unchanged 116-case matrix. The 125 ZIP files matched evaluated bytes. Those unpublished archive names/hashes are historical; the document says the archives are absent from the current checkout. Concurrent Chrome messaging failures remained separately disclosed with unestablished precise causes.

[v0.7.1](../../docs/releases/v0.7.1/navigation-fixes.md) fixed the DreamWorks References/footer failure. Dense related-link navigation had consumed a 600-control scan and displaced the actual heading and footer policies. The existing discovery owner reserved structural coverage within the same limit, recognized ARIA banner/contentinfo landmarks and stopped footer links borrowing article-heading context. Discovery and overlays respected ancestor overflow clipping. Section completion required the actual destination fully unclipped in the viewport; a fragment link needed a real matching heading or labelled region. Geometry was cached only within one scan.

Generic question openings such as “Where are the references?” retained the original request. Removing References yielded an unresolved route despite saved knowledge. A partial scan could not prove whole-page absence. Product code acquired no special Wikipedia route or selector. Historical checks included 128 units, 11 model/API/migration tests, 11 NLP browser tests, 86 extension regressions, 16 live regressions and the 116-case matrix. An explicitly rejected responsive stale scan was refreshed by the test client at most three times; the acceptance helper waited for general next-step readiness before unchanged exact target/outcome assertions. Failed reports and a startup trace were retained.

## Contextual multi-app architecture and incomplete v0.8.0 final evidence

The [v0.8.0 architecture](../../docs/releases/v0.8.0/architecture.md) assigned workflow interpretation/planning to `packages/navigation-core` and live discovery, binding and verification to the extension. Entity slots, milestone predicates, evidence, surface coverage and control references had validated contracts. The original request and three-task queue stayed separate from internal workflow milestones. Versioned guides contained no selectors, coordinates, account identifiers or automatically followed destination URLs.

Incremental discovery used approximately 8 ms slices, a tab-wide **5,000-control registry** including authorized frames and a **600-control planning projection**. Structural/global controls and active dialogs received priority; omissions and virtualized content stayed explicit. Current geometry, clipping, availability and modal occlusion were live evidence. Frame references bound tab, frame, Chrome document and control, with nonce and browser sender checks. Denied embedded origins exposed selective recovery; all frames shared the budget. The `tabs` permission fixed missing active-tab URL before host grant, but scanning still required explicit access to the selected fresh origin and rejection of tab/origin changes during approval.

Storage failures drove the bounded background memory queue. Guidance and panel polls read committed cache rather than waiting on writers. Ordinary observations coalesced while distinct verified edges survived. IndexedDB transactions aborted after five seconds; Forget/Clear drained the current writer and discarded pending writes before deletion. Derived cache reads exceeding 200 ms fell back to CPU, background writes ceased to block inference, and worker errors/30-second deadlines settled pending calls. Cold memory hydration gained a deletion epoch so a late read could not resurrect cleared data.

Private application memory kept only allowlisted reusable interface semantics durable. Unknown item text, private paths, supplied values, option names, statuses and embeddings remained trusted session data or inference memory. IndexedDB v4/SQLite migrations sanitized affected platform semantics and unknown-provenance derived embeddings while preserving original public knowledge. The optional v2 API retained v1 compatibility, revision-stamped requests/results, bounded delta assembly and 409 on a stale delta base. Browser IndexedDB remained authoritative, with old-backend/failure/pending-inference fallback to local planning.

The [v0.8.0 validation table](../../docs/releases/v0.8.0/validation.md) explicitly leaves the **final live run in progress** and **original accuracy final run pending**. Its reported passed suites and later isolated fixes do not justify inventing a completed final release gate. The document also describes multiple distinct failures: memory work blocking the guidance queue, synchronous derived-cache dependencies, missing cold hydration and a `choose` intent omitted by a reveal-only picker guard. Traces and failed reports were retained; no assertions, frozen expectations or deadlines were relaxed.

The frozen 360-case corpus tested first grounded targets on initial-screen fixtures. Five platforms achieved 28/28 held-out positive precision/coverage; GitHub retained **27/28 = 96.4%**, with “Change the default branch to dev in that repository” selecting **Search repositories** rather than **Settings**. This miss remains evidence, not a deleted outlier. Initial-target accuracy is not a signed-in workflow pass.

The [capability matrix under v0.8.0](../../docs/releases/v0.8.0/capabilities.md) explicitly calls itself **current coverage** and retains its filename for links. It includes later Prime, Tesseract and Paddle status, so the directory is not an immutable release date for every statement. It separates guide purposes, first-target corpus, complete simulated journeys, real model inference and signed-in checks. Cloudflare, GitHub, Jira Cloud, YouTube, Netflix and Amazon account workflows all retain pending real checks. Official guide provenance and fetched-content hashes live in `packages/navigation-core/guides.ts`.

## Continuous journeys and masked OCR

[v0.9.0](../../docs/releases/v0.9.0/validation.md) kept objective, values, exclusions and outcome predicates independent from the current document or control. Every 25 verified interactions created a compact checkpoint; detailed history stayed bounded to 30 events. Heap search dropped the twelve-step cutoff and preserved its frontier between planning slices. Exhausting a planning budget did not complete a task. Five unfinished journeys could be parked in trusted session storage, always requiring fresh observation to resume. Browser Back named one observed predecessor; forward interactions were never assumed reversible.

Pinned offline Tesseract ran in a separate worker when refreshed DOM discovery lacked evidence. OCR label embeddings were session-only; visual suggestions used dashed highlights and retained unknown effects. Image confidence could not establish action effects or completion. Capture covered only the active authorized HTTP/HTTPS viewport, hid overlays, masked editable fields and unknown/unverified frame mappings, and canceled stale work on navigation/viewport/interactions. Explicit backend OCR allowed temporary image transmission to the configured authenticated service; PNG dimensions and 4 MB/4 MP limits applied, with no SQLite access from the OCR worker. The frozen 64-case Cloudflare/GitHub route corpus measured next targets, not signed-in execution. Creation required a fresh named receipt or created-item signal; a matching repository heading alone was insufficient.

The [v0.9.1 reliability snapshot](../../docs/releases/v0.9.1/validation.md) is explicitly the **packaged pre-cleanup candidate**, not the current default build. It retained destinations through credentials and delayed OTP metadata without reading input/editor contents. Review clicks did not complete cancellation; Prime-specific status had to name Prime and confirm cancellation. The one-request simulated journey covered a three-minute wait, menus, retention, review and status with pregranted fixture permissions. It did not test a native grant dialog or certify signed-in Amazon reliability.

Masking strengthened to **every iframe rectangle**, even where the frame had DOM access permission. Authorization alone did not provide reliable field-mask geometry. Authorized frame-local DOM discovery remained supported, but in-frame OCR guidance was unavailable. This is a concrete evolution from the earlier unknown/unverified-frame masking language, not interchangeable wording.

The frozen authored UI corpus contained 32 images: eight calibration and 24 held-out, including 15 eligible positive targets. Real offline Tesseract achieved 100% accepted-region precision/coverage on that held-out fixture split and warm p95 106 ms on 960×600 images. These were simulated UI images, not authenticated screenshots or a promise for every real page.

### Paddle never passed promotion

The historical v0.9.1 archive bundled PaddleOCR.js 0.4.2 and PP-OCRv6 tiny detector/recognizer assets with pinned hashes. OpenCV function generation was adapted to static closures without weakening extension CSP; its image adapter used OffscreenCanvas pixels. **Initialization still timed out. Paddle had no passing held-out score and no passing latency measurement.** The comparison test completing was explicitly insufficient to call the Paddle promotion gate successful. It remained experimental and disabled by policy.

The [maintenance cleanup](../../docs/releases/records/2026-10-maintenance.md) removed disabled Paddle/OpenCV chunks and models from normal builds while preserving the opt-in experimental source, pinned assets and comparison tests. Switching back to normal builds removed leftover experimental output with path checks. The default extension fell from the historical 76,271,843 bytes/72.7 MiB to 59,052,883 bytes/56.3 MiB and 151 assets. Cleanup Tesseract again scored 100% on 24 held-out images/15 positives with warm p95 108 ms; Paddle was explicitly reported **not bundled**, with no accepted score. Later v0.10.0 also kept Paddle excluded and unpromoted.

## Focused navigation, presentation and maintenance evidence

[v0.9.2](../../docs/releases/v0.9.2/navigation.md) allowed a fresh named account/profile/user menu to be a grounded intermediate route when Account settings was not yet mounted. It retained the account qualifier through rebinding and navigation; repository/product Settings could not substitute. Accessible SVG names supplied semantics without guessing icon shapes. Relevant exploration could run while embeddings loaded; a backend lacking `settings-navigation` fell back locally. The document reports 169 units, 11 NLP, 17 multi-app and eight focused browser cases. It explicitly says full release suites were not rerun, no replacement archive was produced, signed-in checks remained pending and the earlier GitHub default-branch miss was unresolved.

[v0.10.0, evaluated 14 October](../../docs/releases/v0.10.0/validation.md), added the Tholi sidebar, Conversation, widget, responsive website and mock onboarding evidence. Tests checked isolated storage, fresh widget registration, cloned-frame rejection, capture exclusion and real pointer dragging/resizing. Local packaging matched all ZIP members and the website download checksum; no site was published. The 61,723,341-byte candidate differed from earlier archives. It reported 178 units and the listed browser/model/API suites, including 14 tests over 116 matrix cases.

Performance limitations remained explicit: a dense mutation fixture retained one highlight root but had JavaScript frame-gap p95 **266.8 ms** and rendering stalls. Warm 1920×1080 OCR p95 was 494.4 ms. These metrics did not establish smooth busy dashboards. Native sidebar activation/closure, real permission/capture recovery, screen-reader speech, keyboard widget handles and signed-in Amazon/Cloudflare/GitHub were pending.

The [maintenance record](../../docs/releases/records/2026-10-maintenance.md) contains several subsequent, separately scoped stages:

- Cleanup consolidated five build-hashing implementations into `scripts/artifact-files.mjs`, enabled unused-code checks, removed duplicate presentation/actions, scoped visual invalidation to active sessions and removed an automatic Resume that could release an explicit Pause/login checkpoint. Demo and live adapters intentionally retained different contracts. Cleanup passed focused suites but did **not** rerun full live Wikipedia, acceptance and all remaining release suites at that stage.
- On 16 October, a notice guard hid denied-frame recovery during idle exploration. An observation-scoped frame-access projection made recovery available before a goal and while planning while suppressing obsolete paused/terminal prompts. Host grants, discovery and outcome rules stayed intact.
- Late initial `UI_GET` could overwrite a typed destination. Local revisions, matching save acknowledgements, old-snapshot rejection and unmount guards fixed the race. Widget tests used real frame clicks; cookie keyboard tests waited for Base UI focus transfer. No retry or timeout increase supplied the fix.
- Expected cross-origin authentication pauses regained their active continuation action without reviving explicitly paused/stopped/completed/canceled prompts. Headless export failures were fixed in the disposable browser adapter by configuring the actual CDP download context and preserving real website context. The product Blob exporter and installed-browser permissions stayed unchanged; native sidebar/download prompts remained untested.
- Acceptance learned that a fresh semantic final outcome can precede an interaction receipt, but only for the same completed request/journey plus an independent true DOM oracle. Focus and menu opening retained their exact one-step receipt requirement.
- A saturated 600-control language projection could omit the original opener. Handoff evidence was restricted to an incomplete projection and a matching named dialog with fresh visible ordinary expanded combobox, bound to the same task/origin; later pending-click index-gap recovery also required the same frame. Present closed openers, unrelated/hidden/occluded/consequential/stale/foreign evidence could not verify the requested choice.
- Stale-plan installation rescheduled only an explicitly rejected result for the same running task, preserving newer plans and ended sessions. Live runners followed scroll guidance before fresh in-viewport clicks. Progress polling stopped transferring the full 600-control snapshot while independent full target/outcome checks remained.

Final maintenance verification completed **17 October 2026**: all 12 local commands passed, totaling **476 unique automated tests**: 271 core, 11 NLP, 17 multi-app, four vision, 90 extension, 12 NLP browser, seven multi-app browser, three continuity, two reliability, 29 UI, 16 live and 14 acceptance. Eleven gate reports bound the same 272 extension assets; website checks bound 37 built files plus source/entry HTML, and applicable API bytes matched. The 116 scenarios remained 60 live, 30 controlled and 26 authored; this run recorded **70/70** live targets/verifications and **60/60** supported completions. Earlier 71/72 interaction counts are different historical runs, not contradictory case denominators.

This later record still says GitHub CI had not been rerun, native docking/host/download permission dialogs, screen-reader and signed-in checks were pending, and no commit, tag or replacement extension/backend archive was created. ## Reading the evidence correctly

The [unversioned diagnostic checkpoint](../../docs/releases/records/2026-10-diagnostic-evidence.md) records bounded inspector revisions, score replay, rejection reasons, reveal ownership, real memory provenance and verification-history states. Its strict local export omits page text, goals, paths, field values and model output. Historical 59-unit/40-browser/six-live counts are regression evidence, explicitly separate from measured acceptance.

The [legacy evidence index](../../docs/releases/records/legacy-build-evidence.md) states that preserved measurements and pending checks **do not authorize current packaging**. Across these records, distinguish historical matching-byte reports from current source; deterministic model contracts from real inference; first-target corpora from full journeys; simulated fixtures from public-page or signed-in checks; and semantic progress from final requested results. A pending or failed condition remains pending or failed until corresponding evidence is actually collected.
